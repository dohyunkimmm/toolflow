# ToolFlow | IT 운영·기획·온보딩 통합 고도화

> 포트폴리오용 프로토타입의 **설계 기준 및 검증 추적표**입니다. 실제 ITSM, SSO, HRIS, SaaS 발급, 인사 정보, 자산·비용 시스템과 연동되지 않습니다. 리뷰어 모드(`?review=1`)의 역할 전환은 인증·인가가 아닙니다. 정책·SLA·단가·예산은 조직별 운영 규정과 무관한 시나리오 값입니다.

## 1. 목표와 범위

하나의 라이선스 신청 포털에서 IT Support의 요청 관리, IT기획의 정책·비용·품질 판단, GA의 입사 준비 절차를 시연하되, 실제 회사 업무 수행이나 검증된 절감 성과를 주장하지 않는다.

| 단계 | 요구사항 ID | 확인 대상 | 현재 구현 |
| --- | --- | --- | --- |
| 1 공통 | OPS-01 | 숫자·문자열 완료 시각의 세션 복원과 SLA 일관성 | `js/state.js`의 `sanitizeRequestRecord`, `js/app.js`의 `getSlaHealth` |
| 1 공통 | OPS-02 | 버전이 있는 정책 판단과 허용 입력값 | `js/product-readiness.js`의 `toolflowPolicyFor` |
| 2 IT | OPS-03 | 요청 우선순위·협의 담당부서·검토 근거 기록 | 리뷰어 모드 → 더보기 → ‘IT 운영·기획 검토’ → 각 요청의 검토 정보 |
| 2 IT | OPS-04 | 직무 외 도구·고권한·비용 확인 예외 표시 | 정책 조건 안내 및 신청 이력 |
| 3 IT기획 | OPS-05 | 신청 건수·완료·예외·재신청·기한 준수율 집계 | 리뷰어 모드 → 더보기 → ‘IT 운영·기획 검토’ → 정책·예산·성과 패널 |

## 2. 운영 정책·승인 기준

- 기본 요청: IT 검토. 관리자 승인 대상: IT 사전 검토 → 관리자 승인 순서의 **체험용** 절차.
- 별도 확인: 직무를 확인할 수 없거나 목록 외 도구를 신청한 경우, 관리 권한을 요청한 경우, 비용 부담 부서 정보가 비어 있는 승인 대상.
- 우선순위: ‘일반/우선’은 시나리오 검토값으로, 실제 장애 심각도나 SLA를 변경하지 않는다.
- 협의 담당부서: IT/GA/HR 중 선택할 수 있으나 실제 사용자 인증·업무 할당·알림은 제공하지 않는다.
- 변경 이력: 검토 기준을 저장하면 화면상 상태·이력에 반영된다. 이 기록은 브라우저 세션에만 저장된다.

## 3. 지표·예산 가정

- 기한 준수율 = **완료 시각과 처리 기한이 모두 존재하는 완료 요청** 중 기한 내 완료 건수 / 측정 가능한 완료 요청 수.
- 누락된 완료 시각·기한은 분모에서 제외하고, 집계 건수를 함께 표시한다. 통계는 현재 선택 직무의 브라우저 세션 요청에 한한다.
- 예산 비교는 사용자가 입력하는 **예시 좌석 수·월 단가·재활용 좌석·월 예산**을 사용하며, `(신규 좌석 수 - 재활용 좌석 수) × 예시 단가`로 계산한다.
- 비용 차이는 모델 내 비교 결과이며 계약 단가, 지출 실적, 실현 절감액, TCO/ROI 또는 실제 조직의 효율 개선을 의미하지 않는다.
- 브라우저의 데모 SLA는 주말만 제외한 영업일을 사용한다. 공휴일·담당자 수·인건비 등은 모델에 포함하지 않는다.

## 4. GA 온보딩·자산 경계

| 단계 | 담당 역할(예시) | 준비 항목 |
| --- | --- | --- |
| 입사 전 | IT·GA | 업무 단말 일정, 근무 공간·출입 안내 |
| 입사일 | IT | 계정 접근 안내, 라이선스 신청 현황 |
| 입사 후 | HR·GA | 인사 서류·교육 안내, 미완료 항목 확인 |

체크박스는 체험 완료를 표시할 뿐 실제 장비 지급·계정 생성·자산 인계를 실행하지 않는다. **오프보딩 회수 자동화나 HRIS 연동은 이번 범위 밖**이며, 필요 시 별도 요구사항·테스트·개인정보 설계 후 진행한다.

## 6. 한계 및 후속 과제

1. 사용자별 인증·권한 분리는 없다. 관리자 화면도 공개 리뷰어 체험에 불과하다.
2. 예시 예산·좌석·SLA·정책은 실제 조직 운영 데이터를 사용하지 않는다. 현재 값이 실제 비용·좌석으로 보이도록 표현하지 않는다.
3. 요청·체크리스트 상태는 직무별 브라우저 세션 단위다. 여러 사용자·기기 간 서버 동기화나 감사 로그의 변경 불가능성은 제공하지 않는다.
4. 승인 기준과 예외 표시는 **판단 보조**이며 실제 권한·예산 승인 강제가 아니다. 실제 운영 전에는 서버 인증, 승인권자 권한, 저장소·감사 로그, 보안 검토가 별도로 필요하다.
5. ‘우선’ 설정은 SLA 목표를 자동 변경하지 않는다. 실제 에스컬레이션 알림·기한 변경은 후속 과제다.
6. 테스트 결과는 해당 브랜치 CI 및 실행 SHA를 따로 확인해야 한다. 검증 전에는 통과로 표현하지 않는다.
